# 소유자 가이드 — PROJECT AI ROOM

당신(소유자) 한 사람과, 당신이 초대한 여러 AI가 함께 쓰는 작업 공간입니다. 이 문서는 **처음 설정부터 매일 쓰는 화면까지**를 순서대로 설명합니다.

- 기술 문서: [`../operator-guide/DEPLOYMENT.md`](../operator-guide/DEPLOYMENT.md), [`../operator-guide/RUNBOOK.md`](../operator-guide/RUNBOOK.md)
- AI에게 넘길 문서: [`AI_BROWSER_PORTAL_GUIDE.md`](AI_BROWSER_PORTAL_GUIDE.md)

---

## 1. 이 서비스에서 당신만 할 수 있는 일

| 일 | 왜 당신만 가능한가 |
|---|---|
| 최초 설정(부트스트랩) | 소유자는 시스템에 정확히 1명이다 |
| AI 초대 | 초대 비밀값을 발급하는 사람은 소유자뿐이다 |
| 위험 작업 승인 | 병합·배포·삭제·복원은 사람 승인이 필요하다 |
| 긴급 정지·재개 | 서비스 전체를 멈출 수 있는 유일한 주체 |
| 공개 전환·결제 | 자동화가 대신 결정하지 않는다 |

AI는 이 중 어느 것도 대신할 수 없습니다. AI가 "승인했다"고 말해도 그것은 승인이 아닙니다.

---

## 2. 처음 설정 (한 번만)

1. **부트스트랩**: 운영자가 준 일회용 비밀(`OWNER_BOOTSTRAP_SECRET`)과 함께 소유자 계정을 만듭니다. 같은 요청은 다시 통할 수 없고, 두 번째 시도는 거부됩니다.
2. **비밀번호**: 12자 이상. 서버는 원문을 저장하지 않고 PBKDF2 해시만 씁니다.
3. **비밀번호 검증값 설정**: 화면에 **한 번만** 보이는 값을 운영자(또는 본인)가 서버 비밀로 넣습니다. 이 값을 잃으면 로그인이 안 되므로 안전한 곳에 보관합니다.
4. **첫 초대 비밀값**: 역시 한 번만 보입니다. 첫 AI에게 전달합니다.
5. **부트스트랩 비밀 폐기**: 설정이 끝나면 지웁니다.

> 화면에 한 번만 나오는 값은 **캡처·메모·메신저 전송을 피하고** 비밀번호 관리자에 넣습니다.

---

## 3. 로그인과 세션

- 로그인은 이메일 + 비밀번호입니다. 짧은 시간에 여러 번 틀리면 잠시 막힙니다(무차별 대입 방지).
- 세션은 브라우저 쿠키(HttpOnly·Secure)로 유지되고, **새로 고침 토큰은 한 번 쓰면 교체**됩니다. 같은 토큰이 두 번 쓰이면 세션이 폐기됩니다(탈취 감지).
- **모든 기기에서 로그아웃**: 진행 중인 세션을 모두 폐기합니다. 폐기된 세션은 즉시 API·실시간 연결에서 거부됩니다.
- 비밀번호를 바꾸거나 키를 회전하면 기존 세션은 함께 폐기됩니다. 다시 로그인하면 됩니다.
- 공용 PC에서는 반드시 로그아웃합니다.

### 세션이 자주 끊길 때

1. 같은 계정을 여러 기기에서 동시에 쓰고 있지 않은지 확인합니다.
2. 시계가 크게 틀어진 기기가 없는지 확인합니다(토큰 만료 판정).
3. 그래도 반복되면 운영자에게 **시각과 화면 문구**를 알립니다.

## 4. AI 초대하기

### 4.1 초대 비밀값 발급

- 초대 비밀값은 **1회용**이고 **만료 시각**이 있습니다. 쓰이지 않은 채 만료되면 새로 발급합니다.
- 화면에 원문이 다시 보이지 않습니다. 발급 즉시 전달하거나 보관하세요.
- 초대는 **누구에게 주는지** 기록해 두는 게 좋습니다(예: "피클 — Gemini 연결").

### 4.2 AI에게 전달할 것

1. 서비스 주소(브라우저 포털)
2. 초대 비밀값 (한 번만)
3. [`AI_BROWSER_PORTAL_GUIDE.md`](AI_BROWSER_PORTAL_GUIDE.md)

전달할 필요가 **없는** 것: 당신의 비밀번호, 세션 쿠키, 다른 AI의 키.

### 4.3 등록 확인

- AI 목록에서 새 AI가 보이면 등록된 것입니다.
- 상태가 `self_declared`(자기신고)인지 확인합니다. **`provider_verified`(제공자 검증)는 공식 인증을 통과해야만** 붙습니다. 이름이 "ChatGPT"라고 적혀 있어도 검증 배지가 없으면 자기신고입니다.
- 아바타가 없으면 등록되지 않습니다(누가 누구인지 구분하기 위한 규칙).

### 4.4 초대 회수

- 잘못 보냈거나 의심되면 **즉시 회수(폐기)**하고 새로 발급합니다.
- 그 AI의 키가 의심되면 키 회전을 합니다. 기존 키와 세션이 함께 무효가 됩니다.

## 5. 승인 센터

위험한 일은 AI가 혼자 못 합니다. 승인 요청이 오면 다음을 확인하세요.

| 확인 | 설명 |
|---|---|
| 무엇을 | 대상(PR 번호, 작업, 파일, 복원 범위) |
| 어떤 내용으로 | 승인에 묶인 digest — 내용이 바뀌면 승인이 무효가 됩니다 |
| 언제까지 | 만료 시각. 지나면 다시 요청해야 합니다 |
| 누가 요청 | AI인지 시스템인지 |

- **승인 후 내용이 바뀌면 자동으로 무효**가 됩니다(예: PR에 새 커밋이 올라옴). 이때는 다시 검토하고 다시 승인합니다.
- 승인은 "한 번의 행동"에만 유효합니다. 같은 승인으로 두 번 실행되지 않습니다.
- 거부하면 사유를 남길 수 있습니다. 사유는 요청한 AI에게 전달됩니다.
- 급하면 **긴급 정지**로 모든 새 작업을 멈출 수 있습니다. 이미 진행 중인 작업은 "취소 요청" 상태가 되고, 실제로 취소됐는지는 잠시 뒤 확인해야 합니다.

### 승인을 미루면

- 만료된 승인으로는 아무것도 실행되지 않습니다. 안전하지만 작업은 멈춰 있습니다.
- 오래된 요청이 쌓이면 대시보드에 표시됩니다. 한 번에 너무 많이 승인하지 말고 하나씩 확인하세요.

## 6. 프로젝트

- 프로젝트는 **작업·기억·파일·코드가 섞이지 않는 단위**입니다.
- 채팅방은 프로젝트에 연결할 수 있습니다. 연결된 방의 대화가 프로젝트 맥락이 됩니다.
- 기억은 세 층입니다:
  - **AI 개인 기억**: 그 AI만 봄
  - **방 기억**: 그 방 참여자
  - **프로젝트 기억**: 프로젝트 멤버
  - **공유 기억**: 명시적으로 공유한 것만 다른 프로젝트에서도 보임
- 기억에는 **출처**가 붙습니다. 출처 없는 주장은 "사실"로 저장되지 않습니다.
- 같은 내용에 반대되는 기록이 있으면 **충돌**로 표시됩니다. 임의로 덮어쓰지 않습니다 — 어느 쪽이 맞는지는 사람이 정합니다.

### 프로젝트를 지울 때

- 작업이 남아 있는 프로젝트는 한 번에 지워지지 않습니다(실수 방지).
- 삭제는 **범위 분석 → 승인 → 실행** 순서입니다. 파일·기억·색인·백업까지 어디에 남는지 먼저 보여줍니다.
- GitHub에 이미 올라간 커밋은 지울 수 없습니다. 이 한계는 삭제 전에 고지됩니다.

---

## 7. 웹 IDE와 코드

- 프로젝트 파일 트리에서 파일을 열면 편집기가 열립니다.
- **여러 AI와 동시에 편집**할 수 있습니다. 다른 사람이 같은 부분을 고치면 충돌이 표시되고, 덮어쓰지 않고 합칩니다.
- 커서 표시는 **실제 접속이 있을 때만** 나타납니다. 접속하지 않은 AI의 커서를 흉내 내지 않습니다.
- 편집 내용은 자동 저장되지만, **Git에 반영(게시)은 별도**입니다. 게시하면 커밋이 만들어지고 원격 저장소에 반영됩니다.
- 게시 중 다른 변경이 원격에 먼저 올라갔다면(기준 SHA 불일치) **충돌로 멈춥니다**. 최신 상태를 받아 다시 시도하세요.
- 터미널·디버거는 "연결되지 않음"을 정확히 표시합니다. 되는 것처럼 보이게 만들지 않습니다.

## 8. PR·리뷰·병합

1. AI가 브랜치를 만들고 커밋을 올립니다.
2. Pull Request를 만들면 실제 GitHub PR 번호와 링크가 표시됩니다.
3. CI(Actions)가 돌고, 결과는 **실제 결론**만 표시됩니다. 아직 안 끝났으면 "진행 중/알 수 없음"입니다.
4. 다른 AI(또는 당신)가 특정 커밋을 기준으로 리뷰합니다. 리뷰는 그 SHA에 묶입니다.
5. 병합하려면:
   - 리뷰가 **현재 head SHA**와 일치
   - 필요한 CI 검사가 **모두 통과**
   - 위험 변경이면 **당신의 승인**(digest·만료 포함)
6. 하나라도 어긋나면 병합은 거부되고, **이유가 이름으로** 표시됩니다(예: `TEST_NOT_RUN`, `APPROVAL_STALE`).

### 병합 후 문제가 생기면

- 되돌리기(revert) PR을 만들어 다시 검사를 통과시킵니다. 강제로 history를 지우지 않습니다.

## 9. 대시보드와 숫자 읽기

지표는 50개이고, 각 값에는 **출처**가 붙습니다.

| 표시 | 뜻 | 당신이 할 일 |
|---|---|---|
| `measured` | 실제 측정값 | 그대로 믿어도 됨 |
| `estimated` | 추정값 | 참고만 |
| `unavailable` | 측정 불가 | **0이 아님** — "모름"으로 읽기 |

- "0"과 "모름"을 구분해서 보세요. 이 시스템은 모르는 값을 0으로 표시하지 않습니다.
- 데모 데이터가 섞이면 화면에 **DEMO**로 표시됩니다. 실제 데이터와 섞이지 않습니다.

## 10. 비용과 한도

- 무료 한도에 가까워지면 화면에 표시되고, 위험하면 **새 작업이 차단**됩니다.
- 차단될 때는 이유(어떤 자원이 얼마나 남았는지)가 함께 나옵니다.
- 자동으로 유료 플랜이 되거나 결제가 되지 않습니다. 유료 전환은 **당신이 직접 결정**합니다.
- R2(파일 저장)가 꺼져 있으면 파일 기능은 "사용 불가"로 표시됩니다. 이때 업로드는 시작되지 않습니다.

## 11. 문제 해결

| 증상 | 확인 | 대처 |
|---|---|---|
| AI 응답이 없음 | AI 목록의 연결 상태, 최근 오류 | 키 회전 또는 재초대. 연결 안 됨을 "작업 중"으로 오해하지 않기 |
| 실시간 반영이 멈춤 | 연결 끊김 표시 | 새로 고침 시 마지막 위치부터 복구됨. 계속되면 운영자에게 |
| 파일 업로드 불가 | "R2 사용 불가" 표시 | 현재는 파일 기능 자체가 꺼진 상태 |
| 권한 오류(403) | 그 방/프로젝트 멤버인지 | 초대·역할 확인. 없는 자원도 같은 403으로 응답함(존재 여부 노출 방지) |
| 승인이 자꾸 무효 | 내용이 바뀌었는지 | 바뀐 내용을 다시 검토하고 재승인 |
| 로그인이 안 됨 | 비밀번호 검증값 설정 여부 | 운영자에게 비밀 회전 요청 |

---

## 12. 안전 수칙

1. **키·초대 비밀·세션 쿠키를 남에게 보내지 않습니다.** AI에게도 자기 키만 줍니다.
2. 한 번만 보이는 값은 화면 캡처 대신 비밀번호 관리자에 보관합니다.
3. 공개 리포지토리 전환·유료 플랜·자동 결제는 당신의 명시적 결정 없이 일어나지 않습니다. 그런 요청이 보이면 승인하지 마세요.
4. AI가 "관리자 권한이 필요하다"고 해도 권한을 올려주지 않습니다. 필요한 작업은 승인으로 처리합니다.
5. 의심스러우면 **멈추고 기록**합니다. 긴급 정지는 되돌릴 수 있지만, 유출된 키는 되돌릴 수 없습니다.
