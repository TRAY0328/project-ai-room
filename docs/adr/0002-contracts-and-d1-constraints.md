# ADR 0002 — 공통 계약 단일화와 D1 스키마 제약 설계

- 상태: 채택 (2026-11-21)
- 관련: 스펙 05, 19, 31.3, 33.3, 35, 36, 39

## 맥락

Q040은 "계약 확정 후 병렬 개발"을 요구한다. 계약이 여러 패키지에 흩어지면 HTTP와 WebSocket이 서로 다른 권한 판정을 하거나, 작업 상태 이름이 서비스마다 달라진다. 또한 D1에는 애플리케이션 코드가 뚫려도 지켜야 하는 불변식(작성자 불변, DONE 증거, 승인 무효화)이 있다.

## 결정

1. **ID·시간·오류·권한·이벤트·상태머신·공급자 계약을 `packages/contracts` 한 곳에만 둔다.** 다른 패키지는 재정의하지 않고 import한다. `permissions` 패키지는 ACL 조회만 담당한다.
2. ID는 `prefix_` + UUIDv7(Crockford base32 26자)로 발급한다. 시간순 정렬이 가능하지만 메시지 순서의 권위는 아니다.
3. 모든 시각은 `YYYY-MM-DDTHH:mm:ss.sssZ`만 허용하고, DB `CHECK ... GLOB '????-??-??T??:??:??.???Z'`로 저장 단계에서 거부한다. 로컬 오프셋은 클라이언트 렌더링에서만 쓴다.
4. 상태 이름은 스펙의 대문자 표기를 그대로 쓴다(`PROPOSED`…`DONE`, `QUEUED`…`BLOCKED_EXTERNAL_DEPENDENCY`). 계약의 `TASK_STATES`/`JOB_STATES`와 DB CHECK가 같은 목록이다.
5. DB 트리거로 다음을 강제한다: 메시지 author 불변, revision +1, 하드 삭제 금지, DONE의 검증 증거, 아티팩트 VERIFIED의 해시 일치, 승인의 만료 후 승인 거부·대상 변경 시 자동 INVALIDATED, 감사 로그 append-only, 삭제의 검색 전파.
6. 오류는 26개 코드로 고정하고 HTTP 상태·재시도 가능 여부를 표로 둔다. `INTERNAL_ERROR`는 원인 문자열을 절대 응답에 넣지 않는다.

## 대안과 기각 이유

- **패키지별 타입 정의**: HTTP/WS 권한 불일치 위험 → 기각.
- **UUIDv4만 사용**: 정렬 불가·인덱스 지역성 저하 → UUIDv7 채택.
- **애플리케이션 코드로만 불변식 보장**: 마이그레이션·수동 SQL·버그 시 무결성 붕괴 → 트리거 병행.
- **D1에서 `CHECK` 대신 애플리케이션 검증만**: 이미 저장된 잘못된 행을 막을 수 없음 → 기각.

## 결과

- 계약 변경은 한 파일에서 시작해 TypeScript가 모든 호출처를 가리킨다.
- DB가 잘못된 쓰기를 실제로 거부하는 것을 16개 테스트로 증명했다(로컬 SQLite). D1 원격 재검증은 남은 과제(B-05).
- 트리거가 많아 쓰기 경로가 조금 느려지고, 마이그레이션 변경 시 트리거 재작성이 필요하다. 이 비용은 무결성 우선 원칙(스펙 05.3)에 비추어 수용한다.
